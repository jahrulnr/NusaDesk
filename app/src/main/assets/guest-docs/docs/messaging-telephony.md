# Messaging and telephony

Read-only, bounded guest surfaces:

- `contacts.list` - contacts snapshot
- `calllog.list` - call log snapshot
- `sms.inbox` - SMS inbox snapshot
- `telephony.info` - device telephony information
- `telephony.cellinfo` - serving cell information

All reads use fixed defaults and return bounded rows. The response
reports `count`, and rows dropped by the byte bound set
`truncated` = `true`. Permission, denial, unavailability, and
no-telephony states are typed errors.

Side-effecting operations run only with their own per-call grant,
and a missing grant is a typed result, never a silent action and
never a prompt from the bridge worker:

- `sms.send` - real SMS through the platform `SmsManager`; needs
  `SEND_SMS` (plus `READ_PHONE_STATE` when a SIM slot is named).
  Each recipient is reported as `sent`, `failed`, or `unconfirmed`
  (the `termux-sms-send` command prints the lists and exits 1 when
  any recipient is not `sent`). When the platform never delivers a
  part's result broadcast, a dispatched part is confirmed against
  the platform sent box only if `READ_SMS` is already granted; the
  send path itself never demands read access.
- `phone.call` - places a call through the foreground host, because
  the platform drops a background `ACTION_CALL`; needs `CALL_PHONE`.
