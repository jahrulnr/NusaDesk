# Battery, sensors, and location

## Battery

- `battery.status` - one Android BatteryManager snapshot
- `/sys/class/power_supply/battery` - a best-effort app-owned
  projection refreshed every two seconds while the session is live.
  It is not real kernel sysfs; treat it as an app snapshot and let
  the app own it.

## Sensors

- `sensor.accelerometer` - one-shot accelerometer reading
- `sensor.gyroscope` - one-shot gyroscope reading
- `sensor.list` - the full sensor catalog (bounded rows,
  `truncated` flag; step sensors carry a `requires` marker for
  the ACTIVITY_RECOGNITION grant)
- `sensor.read` - a bounded read of named sensors or `all`
  (`count` 1..10, `delay_ms` up to 5000)
- `sensor.stream.start|poll|stop` - one pull stream at a time;
  poll returns the latest coalesced sample

Unavailable and timeout states are typed errors. The installed
client for `sensor.list`, `sensor.read`, and `sensor.stream.*` is
the optional Termux toolkit's `termux-sensor` - there is no core
`nusadesk-*` sensor client.

## Location

Foreground pull surfaces live only while the bridge session is
live and never open a permission prompt:

- `location.get` - one foreground one-shot fix
- `location.stream.start` - start one foreground pull stream at a
  fixed 5 second interval
- `location.stream.poll` - read the next fix with a bounded wait
- `location.stream.stop` - idempotent stop

The optional Termux toolkit's `termux-location` only calls `location.get`.
`-r once` waits for one fix; `-r last` reads a last-known fix;
`-r updates` still returns one fix and warns on stderr. There is
no shipped CLI for `location.stream.*`; those are separate bridge
methods, not a stream hidden behind `termux-location`.

Background location is a separate opt-in surface:
`location.background.start|poll|stop` runs under a visible
`location` foreground service that keeps fixes after the caller
returns. It only runs behind the 'Allow all the time' grant -
on Android 11+ there is no runtime dialog for it, so a missing
grant answers `location-background-permission-required`
pointing at app settings (Android 10 can still grant it from a
runtime prompt). Client: `nusadesk-loc start [--provider
gps|network|passive] [--interval-ms N] [--distance-m N] | poll
| stop`; `poll` drains a bounded buffer (at most 100 fixes per
call) and `stop` is idempotent.
