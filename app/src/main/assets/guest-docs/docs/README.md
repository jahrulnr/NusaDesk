## Command-line tool

`nusadesk-android` is installed at `/usr/local/bin/nusadesk-android`:

- `nusadesk-android media start [--camera|--microphone]` - live
  media session (camera, microphone, or both)
- `nusadesk-android media outputs|route DEVICE_ID|route clear` -
  list outputs or route NusaDesk's own media player
- `nusadesk-bt hid start|status|connect|type|key|mouse|stop` -
  use this phone as a bounded keyboard/mouse HID device
- `nusadesk-bt audio status|voice start|voice stop` - HFP/profile
  status and voice recognition for an already-connected headset
- `nusadesk-android calendar list` - next seven days of events
- `nusadesk-android calendar add --title TITLE --begin-ms EPOCH
  --end-ms EPOCH [--all-day] [--location LOCATION]` - create one event
- `nusadesk-android calendar update EVENT_ID [--title TITLE]
  [--begin-ms EPOCH --end-ms EPOCH] [--all-day|--timed]
  [--location LOCATION]` - change one event
- `nusadesk-android calendar delete EVENT_ID` - remove one event
- `nusadesk-android bridge info` - bridge discovery
- `nusadesk-bt status|devices|discover|pair|le-scan|advertise|
  gatt|rfcomm ...` - Bluetooth control, BLE, GATT, and serial
- `nusadesk-serve start [--port N] [--dir PATH]` - serve the
  workspace over HTTP on the LAN; `nusadesk-net lan-ip` finds the
  address to hand out
- `nusadesk-wifi hotspot|suggest|lock ...`, `nusadesk-pkg
  list|info|launch`, `nusadesk-usage query|events|standby`,
  `nusadesk-overlay show|update|status|hide`, and `nusadesk-loc
  start|poll|stop` - the native wifi extras, app enumeration,
  usage reads, overlay, and background location
- `android-cli status|doctor|permissions|getprop|toybox|
  toolbox|sh|exec|su` - run the device's own binaries as the
  app uid (the `/system` tree is bound but not on `PATH`)

See [media.md](media.md) for the live stream and capture,
[calendar.md](calendar.md) for the calendar contract,
[termux-compat.md](termux-compat.md) for the optional Termux
command names, and
[bridge.md](bridge.md) for the transport and protocol.

## Optional tools

Two guest tool sets are opt-in (chosen at setup or installed
later from System): the `termux-*` command clients documented
in termux-compat.md, and the USB pass-through set
(`nusadesk-usb`, `nusadesk-usbd`, the `adb` wrapper). Neither is
required for the session itself; each one's state is recorded
under `/var/lib/nusadesk/optional-tools/` once installed.

## Agent bundle

`/root/.agents/` is seeded for AI agents working in the guest:
a durable `AGENTS.md` plus starter skills, including the
Termux-API-vs-`android-cli` decision. Unlike these generated
docs the seeded files are user-owned - the app updates one
only while it is byte-identical to the installed copy and
never recreates a deleted one.
